# Critique

Modified adaptation of Impeccable's `critique.md`, design assessment and priority findings. Source and licence details are in the skill's provenance.

Resolve the target to a specific page, component, or source path.
Preserve a read-only scope when the user requests a review rather than changes.

## Design assessment

Judge the rendered result before reading automated findings.
Identify the user's primary task and follow that path through representative states.
Evaluate hierarchy, grouping, typography, colour, copy, discoverability, and recovery.
Check whether the composition follows this product's content or merely repeats a category template.
Do not treat familiarity itself as a defect when the brief or task requires it.

Check the page from the relevant audience's perspective, including first-time and keyboard users.
Identify labels, sections, or choices that add effort without helping a decision.
Retain useful information rather than removing content solely to create empty space.

## Combine evidence

Compare the visual assessment with browser measurements and the project's existing checks.
Separate observed defects from hypotheses and personal preferences.
Record selectors, screenshots, viewports, themes, or reproduction steps where they support a finding.
Do not invent scores or issue counts to fill a report structure.

## Report

Lead with the most consequential defect or state that no blocking defect was found within the checked scope.
For each finding, give the location, user impact, evidence, and concrete correction.
Prioritise blocked tasks and accessibility defects before structural and cosmetic issues.
Name useful existing choices that the correction must preserve.
State unchecked states and browser limitations precisely.
