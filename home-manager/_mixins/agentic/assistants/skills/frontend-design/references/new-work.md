# New work

Modified adaptation of Impeccable's `new-work.md`, sections 1, 3, and 6. Source and licence details are in the skill's provenance.

## Preserve what is established

A missing design document does not erase a coherent identity in the code.
Read representative pages, tokens, assets, and shared components before deciding that a new system is necessary.

| Scope | Design decision |
| --- | --- |
| Local extension | Inherit the surrounding composition and resolve only the new content, states, and interaction. |
| New page in an existing product | Keep the visual system and choose a structure that serves this page's task. |
| Authorised redesign | Preserve product facts and required behaviour while replacing only the agreed visual decisions. |

## Make the content lead

Identify whether visitors primarily act, read, evaluate a product, or explore an experience.
Use that purpose to choose information density and the first viewport's content.
For a product page, show useful evidence of the product rather than relying on decorative claims.
For a working interface, prioritise stable structure, clear state, and efficient actions.

Choose a direction that the actual content can support across the whole page.
Do not turn a narrow addition into a concept-selection exercise.
Use real assets when available and verify their origin, permitted use, and delivery path.
Keep synthetic examples distinct from factual claims.

## Build the chosen direction

Carry the chosen type, colour, layout, and interaction rules through the complete path.
Vary density when content priority changes, not merely to make sections look different.
Preserve semantics, accessibility, performance, responsiveness, and project conventions.
Record durable design decisions in the project's existing documentation only when that work is within scope.
